# Binz Poker

An autonomous poker simulation where LLM-driven players with randomized personalities compete for survival at a No Limit Hold'em table, managed by an Elixir/Phoenix OTP application.

## Architecture

Two event-driven OTP processes and up to 10 reactive Player agents:

- **Table** — The poker engine. Manages seats, runs hands continuously, broadcasts results. Complete NLHE with proper betting rounds, side pot calculation, and split pots.
- **Sim** — The world reactor. Reacts to events (player busts, hand results, seat availability) and manages economy, seating, eliminations, and respawns.
- **Player** — Reactive agents. Respond synchronously when asked for poker decisions or buy-in decisions. Each player has a unique personality generated by an LLM.
- **Bank** — Tracks budgets, processes token billing, and manages loans.

### Economy

Two currencies:
- **Budget** (real $) — pays thinking tax (token costs from LLM calls)
- **Chips** (table currency) — won/lost at poker. 1 chip = $0.01

Starting budget is $5.00 with 0 chips. Players buy in (budget -> chips) when entering the table and choose how much to convert. When leaving, chips auto-convert back to budget. Death = budget $0 + chips 0 + loan denied.

### Decision Engines

Swappable via configuration:
- `DecisionEngine.Random` — Makes random decisions from available actions (default, simulated token costs)
- `DecisionEngine.LLM` — Calls LLM via LiteLLM gateway for poker decisions with full game context

### Persistence

All state persists to SQLite via Ecto. GenServers cache state in memory and write through to DB on every change. The program can be stopped and resumed — on startup, Sim loads the current simulation and all living players from DB.

Tables:
- `sims` — Simulation config and hand count
- `players` — Player state (chips, budget, personality, stats)
- `loans` — Loan records
- `leaderboard_entries` — Dead players hall of fame
- `hand_histories` — Full audit trail of every hand played

## Setup

```bash
mix setup        # Install deps, create DB, run migrations
```

## Running

### Start the poker simulation

```bash
# Start with the game running
iex -S mix phx.server
```

Then in IEx:
```elixir
BinzPoker.Room.start()   # Start a new simulation
BinzPoker.Room.status()   # Check current status
BinzPoker.Room.stop()     # Pause the simulation
BinzPoker.Room.resume()   # Resume a paused simulation
```

### Configuration (config/dev.exs)

```elixir
config :binz_poker, start_game: true          # Auto-start game on boot
config :binz_poker, action_delay_ms: 3000     # Delay between player actions
config :binz_poker, hand_delay_ms: 5000       # Delay between hands
config :binz_poker, decision_engine: BinzPoker.DecisionEngine.Random
```

## API Endpoints

All endpoints are JSON under `/api`:

### Read-only
- `GET /api/table/state` — Current table state
- `GET /api/players` — All living players
- `GET /api/players/:player_id` — Player detail (stats, personality, billing)
- `GET /api/leaderboard` — Top survivors by hands survived
- `GET /api/sim/status` — Current simulation status
- `GET /api/hands` — Recent hand history (default 20, `?limit=N`)
- `GET /api/hands/:hand_number` — Full hand detail (cards, actions, pots, showdown)

### Banker Controls
- `POST /api/banker/mode/auto` — Switch to auto-approve loans
- `POST /api/banker/mode/manual` — Switch to manual loan approval
- `GET /api/banker/loans/pending` — List pending loan requests
- `POST /api/banker/loan/:id/approve` — Approve a loan
- `POST /api/banker/loan/:id/deny` — Deny a loan

### Table Controls
- `POST /api/table/pause` — Pause the table
- `POST /api/table/resume` — Resume the table
- `POST /api/banker/kick/:player_id` — Kick a player
